# MOMent AI — deployment checklist

Target: a public MVP with the frontend on Vercel, Django API on Render, and PostgreSQL on Neon.

> Important: source code and CI checks do not mean the application is live. A real deployment still needs the owner's hosting accounts, database connection string, and (optionally) an OpenAI API key.

## 1. Neon PostgreSQL

1. Sign in to Neon and create a project named `moment-ai`.
2. Choose a region close to the users (for example, Singapore if available).
3. Copy the PostgreSQL connection string from the Neon dashboard. Keep it private.
4. Do not commit the connection string or paste it into public GitHub files.

## 2. Render API

1. Sign in to Render and choose **New → Blueprint**.
2. Connect the `sri-builds-with-ai` GitHub repository.
3. Select branch `feature/moment-ai-live-launch` for the first deployment.
4. Set the Blueprint file path to `projects/01-moment-ai/backend/render.yaml`.
5. Configure the prompted environment values:
   - `DATABASE_URL`: Neon connection string
   - `CORS_ALLOWED_ORIGINS`: the Vercel frontend origin, e.g. `https://your-app.vercel.app`
6. Keep `DJANGO_SECRET_KEY` generated by Render. Do not reuse the development key.
7. Optional AI drafting: add `OPENAI_API_KEY` and, if needed, `OPENAI_MODEL=gpt-4o-mini`.
8. Deploy and wait for the build and migrations to finish.
9. Check `https://YOUR-RENDER-SERVICE.onrender.com/api/health/`; expected JSON includes `"status":"ok"`.

Render's free web services may spin down when idle. The first request after inactivity can be slow; this is a hosting-tier limitation, not a reminder scheduler.

## 3. Vercel frontend

1. Sign in to Vercel and import the same GitHub repository.
2. Select branch `feature/moment-ai-live-launch`.
3. Set **Root Directory** to `projects/01-moment-ai/frontend`.
4. Framework preset: Next.js. Build command and output directory can use Vercel defaults.
5. Add environment variable:
   - `NEXT_PUBLIC_API_URL=https://YOUR-RENDER-SERVICE.onrender.com/api`
6. Deploy and open the Vercel URL.

## 4. Final CORS handshake

After Vercel provides the real URL, return to Render and set `CORS_ALLOWED_ORIGINS` to that exact origin (no trailing slash), then redeploy/restart the API if required.

## 5. Smoke test on the public URL

- [ ] Health endpoint returns status ok.
- [ ] Frontend loads over HTTPS.
- [ ] Register a new test account.
- [ ] Sign out and sign in again.
- [ ] Create a reminder using the manual form.
- [ ] Refresh the page and confirm the reminder remains.
- [ ] Edit, complete, filter/search, and delete the reminder.
- [ ] Confirm a second account cannot see the first account's reminders.
- [ ] If an OpenAI key is configured, try an AI draft; check that it asks for missing date/time and does not save until the user presses Save.
- [ ] Check mobile layout.

## 6. MVP limitations to communicate

- Recurring reminders and push/email notifications are not implemented in this launch MVP.
- AI drafting is optional and requires an OpenAI API key; manual reminder creation works without it.
- The current browser MVP keeps access and refresh JWTs in localStorage. Before a wider public rollout, move auth behind secure HttpOnly cookies, add rate limiting, and review privacy/security.
- Render free instances can sleep when idle. Do not promise exact-time background notifications from a sleeping web service.
- Use test data only until the security review and notification delivery design are complete.

## 7. Branch and release

Keep the launch work on `feature/moment-ai-live-launch` while testing. Merge to `main` only after the owner reviews the public smoke-test results and approves the merge.
